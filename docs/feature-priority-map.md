# dsh-remote-control 功能盘点与优先级地图

> 建议落盘路径：`docs/feature-priority-map.md`

## 1. 文档目的

梳理本仓库（Kotlin Multiplatform + Compose 的 Android Remote Control App）已实现的功能全集，按「坏了会不会让用户无法遥控桌面 DSH」定优先级，为后续验收、回归测试、排障提供一份可操作的功能地图与 P0 清单。全部结论依据代码事实（`App.kt` / `BridgeClient.kt` / `ConnectionManager.kt` / `protocol/Protocol.kt` / `DeviceRepository.kt` 等）与 `docs/bugs/` 真实故障案例归纳，不臆造代码里不存在的功能。

## 2. 优先级定义

| 级别 | 定义 | 判定关键词 |
|---|---|---|
| **P0** | 故障即中断核心使用：连接断/连不上、消息发不出去、服务端消息/事件推不过来、审批/提问收不到或裁决发不回、关键状态错乱。坏掉后用户**无法遥控 DSH** | 连接、送达、裁决、状态事实源 |
| **P1** | 影响体验或次核心功能受损：可用但明显受限/不完整，或误导用户 | 体验、可读性、控制类、降级 |
| **P2** | 锦上添花、低频、可绕过 | 增强、低频、有替代路径 |

> 两条项目支柱：**① 连接稳定性；② 消息的及时性与准确性**。P0 判定始终以这两条 + 「审批/提问是遥控人机协作的咽喉」为准。

## 3. 连接与配对

- **WebSocket 连接建立与鉴权握手** `P0`
  `ConnectionManager.open()` 发起 WS 握手、注入 `Authorization: Bearer <token>` 头、判定握手成功与否并解码事件流。
  - 故障影响：连不上 = 所有远程能力归零（核心支柱①）。鉴权头缺失/错误 → 服务端拒绝，永远握手失败。
  - 验证信号：真机连 mock-bridge（`tools/mock-bridge`，`PORT=3081`）或桌面端；`ConnLog` 出现「开始握手 → 握手成功，连接已建立」；顶部从「正在连接…」进入会话列表。

- **扫码配对（QR 多候选回退）** `P0`
  `Pairing.parseQr` 支持 bridge 配对 JSON 与裸 `ws(s)://`/`http(s)://`；`connectFromQr` 逐候选尝试，全部失败给完整诊断。
  - 故障影响：主配对口（也是拿长期 token 的唯一自动路径）。扫码解析失败/候选全挂 → 新设备/换设备无法入网（P0：首次建连入口）。
  - 验证信号：扫桌面端「📱 连接移动端」二维码 → 设备页出现该设备且「在线」；`ConnLog` 见「扫码得到 N 个候选地址」「握手成功」。

- **设备注册 + 长期凭据持久化** `P0`
  hello 到达后 `registerIfNeeded` 发 `register_device`（phoneId + name + model）；`DeviceRegistered` 事件把长期 token + serverId + 候选端点写入 `StoredDevice` 并落盘。
  - 故障影响：拿不到长期 token → 断线后无法自动重连（P0：连接稳定性链路的凭据基础）。
  - 验证信号：连接后 `ConnLog` 见「register_device」发送；设备文件里该设备有非空 `token`/`serverId`；桌面端 `/remote/connected` 出现本机。

- **断线自动重连（多候选退避）** `P0`
  `onConnectionLost` 判用户主动断开/切换/凭据 → `startReconnect` 指数退避（1s→30s），每轮按存储端点顺序（USB 127.0.0.1 → LAN → Tailscale）逐路尝试，hello 到达清横幅。
  - 故障影响：断线后无法恢复 = 遥控会话彻底中断（核心支柱①的直接体现）。
  - 验证信号：拔 USB → 顶部横幅「检测到连接断开，正在自动重连…」；重插 + `adb reverse` 后横幅消失、会话数据保留；`ConnLog` 见「hello 到达，重连完成，横幅清除」。

- **手动连接（host/port/token）** `P1`
  落地页手动填地址端口可选 token 直连；127.0.0.1 失败时追加 `adb reverse` 指引。
  - 故障影响：扫码失效时的备用入口；坏掉仍可扫码，故 P1。
  - 验证信号：填 mock-bridge `127.0.0.1:3081` → 「正在连接…」→ 进入会话列表。

- **鉴权错误熔断** `P1`
  收到 `auth/unauthorized/forbidden/token/device_revoked` 错误 → 清空 `reconnectProvider` 停止无效重连。
  - 故障影响：不熔断会无限重连刷屏、占资源；熔断错误则误停有效重连（可用但需重新配对）。
  - 验证信号：桌面端撤销该设备凭据 → 手机停止重试并提示「配对凭据已失效，请重新扫码」。

- **冷启动自动连接上次设备** `P1`
  `autoConnectOnce` 首轮探测就绪后，若上次连接设备在线则直接连，免手动点。
  - 故障影响：坏掉只是每次要手动点「连接」，可用但体验降级。
  - 验证信号：杀 App 重启 → 上次设备在线时自动进入会话列表（`ConnLog` 见「上次设备在线 → 自动连接」）。

- **连接状态统一提示槽（横幅 + 错误历史）** `P1`
  `ConnectionNotice` 单槽三态（Hidden/Reconnecting/Error）互斥；`errors` 分「连接类（hello 自动清）/业务类（手动清）」；点开看错误历史。
  - 故障影响：坏掉 = 横幅过期残留或自相矛盾，误导用户（bug 案例 `connection-notice-stale-error`）；不阻断遥控本身，故 P1。
  - 验证信号：瞬断恢复后横幅自动消失、无「（还有 N 条）」残留；错误历史里连接类错误在 hello 后清空。

- **服务端重启通知（server_boot）** `P2`
  重连后收到 `server_boot` 展示版本 + 新增功能说明，按「serverId + 版本」只提示一次（`BootNoticeCache`）。
  - 故障影响：纯通知，坏掉不影响遥控。
  - 验证信号：桌面端重启服务端 → 手机顶部出现「服务端已重启 · v…」，点「知道了」后同版本不再弹。

## 4. 设备管理

- **设备列表 + 在线探测（12s ping）** `P1`
  `DeviceRepository` 每 12s 探测 `/remote/ping`，标 在线/离线/已更换；连接期间停探测。
  - 故障影响：探测坏掉 = 列表在线状态不准，误导「点哪个设备」（可用但受限）。
  - 验证信号：设备页状态点绿/灰/橙正确；关掉桌面端 12s 内该设备变「离线」。

- **设备切换（先断旧连新）** `P1`
  `connectDevice` 有旧链路时 `switchingDevice` 抑制旧重连，干净断开后再连新设备。
  - 故障影响：切换竞态会踩 `ws/currentUrl`（连接错乱）；不影响单设备遥控，P1。
  - 验证信号：A 设备连接中 → 设备页点 B → 会话界面换到 B，无「两设备同连」矛盾。

- **忘记设备 + 撤销凭据** `P2`
  移除本地记录；若该设备正连接则发 `revoke_device`。
  - 故障影响：坏掉只是列表残留/凭据未撤，不影响当前使用。
  - 验证信号：点「忘记」→ 列表移除；桌面端该设备凭据被撤销。

- **设备已更换检测（serverId 变化）** `P2`
  ping 时 serverId 与存储不符 → 标「设备已更换（点击重连）」。
  - 故障影响：提示类，坏掉可能连错指纹，可绕过。
  - 验证信号：同 host:port 换了一台机器 → 状态点橙色提示重连。

## 5. 会话与对话

- **进入会话（订阅 + 历史返回）** `P0`
  `openSession` 先渲染本地事件缓存，发 `subscribe`；`History` 事件返回最新 300 条 + 队列 + goal/todos/commands/turnSince 等会话态。
  - 故障影响：打不开会话 = 看不到任何消息（P0：读取会话内容的唯一通道）。
  - 验证信号：点会话 → 秒开缓存、随后服务端历史覆盖；`ConnLog` 见「会话历史到达 … 条数=N 耗时=…ms」。

- **发送消息（乐观入队回显 + 失败回滚）** `P0`
  `sendMessage` 运行中先乐观入队显示，再发 `send_message`；发送失败即回滚乐观项并 `pushConnectionError`（不静默丢弃）。
  - 故障影响：消息发不出去 = 遥控失效（核心支柱②）。静默丢弃更是隐蔽的准确性破坏。
  - 验证信号：非运行会话发消息 → 立刻出现「你」气泡；断线时发 → 错误横幅「…未发送」且乐观项消失；`ConnLog` 见「发送消息 sessionId=… running=…」。

- **服务端实时事件推送（增量）** `P0`
  `handle(Event)` 把增量事件（新消息/工具调用/思考/状态）按 `sessionId` 归约进当前会话，100~300ms 送达目标。
  - 故障影响：事件推不过来 = 用户看不到 agent 实时输出（核心支柱②的「及时性」）。
  - 验证信号：桌面端 agent 发消息 → 手机 300ms 内出现气泡；`ConnLog` 见「收到 hello/事件」；切会话后旧会话事件被 `sessionId` 过滤丢弃。

- **历史向上翻页（自动 + 手动）** `P1`
  上滑到最早一条附近自动 `history_page`（`seq < beforeSeq`，每页 300），转盘狩猎也可触发；去重按 `seq-type`。
  - 故障影响：翻页坏 = 只能看最近 500 条（MAX_EVENTS），读不到更早上下文（可用但明显受限）。
  - 验证信号：上滑到顶部出现 loading → 更早历史插入；`ConnLog` 见「翻页返回 … 新增=N 条 hasMore=…」。

- **终止 Agent Loop（interrupt）** `P1`
  会话列表运行中的「中断」按钮 + 会话页圆形终止钮发 `interrupt`。
  - 故障影响：坏掉 = 无法远程停掉 agent（控制类，不影响读取，故 P1；且 bug 案例提醒中断会清排队消息，需注意语义）。
  - 验证信号：运行中点终止 → 桌面端停止推理；`ConnLog` 见「中断会话 … status=running」。

- **会话标题更新（session_title）** `P2`
  服务端推送标题 → 更新列表行显示名（name → cwd basename → id 前缀回退）。
  - 故障影响：纯展示，坏掉标题不更新。
  - 验证信号：桌面端改会话标题 → 手机列表同步。

- **斜杠命令候选弹窗 + 命令行** `P2`
  输入 `/` 且聚焦时弹候选（来自服务端 `commands` 注册表）；`command/run`+`command/done` 合并成一行结果（如 `/compact`）。
  - 故障影响：低频增强，坏掉仍可手敲命令。
  - 验证信号：输入 `/` 弹候选，选中填入 `/命令名 `；`/compact` 出「完成/失败」结果行。

## 6. 消息与队列

- **消息气泡（用户/模型/注入上下文区分）** `P1`
  `user_message` 按 `EventProjection.source`（桥侧分类，`MessageSource`）渲染：`user`→用户气泡、`inject`/其它非空→弱化「上下文」行；`assistant_message` 走 Markdown。
  - 故障影响：分类错乱 = 把注入上下文显示成用户气泡，用户误判「自己说了什么/agent 收到什么」（准确性受损但不阻断遥控，P1；铁律 6 客户端只渲染不推算）。
  - 验证信号：会话含 `<system-reminder>` 注入行 → 显示为左侧「上下文」折叠行而非右侧「你」气泡（bug 修复 `fd4a451`）。

- **Markdown 渲染（含宽表格横滑）** `P1`
  `mikepenz` CommonMark 渲染 agent 正文；表格用自定义 `ScrollableMarkdownTable` 按真实内容宽度横滑，字号移动端档位显式映射。
  - 故障影响：坏掉 = 代码块/表格/加粗显示错乱或宽表格被截断（可读性受损，P1）。
  - 验证信号：发带宽表格 + 代码块的消息 → 气泡内可横滑看全表格、代码块深底可读、标题非 57sp 巨字。

- **工具调用卡 / 结果卡 + Code Diff（失败标红）** `P1`
  `ToolCallCard` 折叠卡（图标+工具名+描述，terminal/read/edit 等分类）；`ToolResultCard` 默认折叠一行、`toolError` 标红；展开 Edit/Write 显示 `CodeDiffBlock` 红删绿增。
  - 故障影响：坏掉 = 看不到 agent 执行了什么命令/改了什么文件（可读性，P1）。
  - 验证信号：agent 执行 `bash` → 出现 `>_` 命令卡；失败命令整卡标红；Edit 卡展开见红/绿 diff 与 `+N −N`。

- **排队消息面板（steer 插队 / remove 删除）** `P0`
  运行中发出的新消息乐观进入队列（`local-` 前缀），服务端 `session_queue` 到达后替换；`QueueAction` 发 steer/remove。
  - 故障影响：运行中发的消息看不到/不可管理 = 消息准确性受损；插队/删除失效 = 无法纠正已排队指令（P0：排队消息是「遥控正在跑的长任务」的关键操作面）。
  - 验证信号：运行中连发多条 → 面板计数递增、每条可「插队/删除」；插队后该条变「⚡插队中」；`ConnLog` 见「排队操作 … action=steer」。

- **消息转盘（MessageDial）** `P2`
  左下角七线半圆旋钮按需显示（上翻离开底部才出现），原地展开为向右开口扇面，单指拨动按用户消息快速定位，触边自动翻更早页（狩猎），2.5s 无操作收起。
  - 显隐语义（2026-09-08 修订）：最新消息不可见时显示；展开/旋转中即使已到底部也保持挂载（手指活动优先于「到底隐藏」），松手后 2.5s 自然收起。
  - 故障影响：定位增强工具，坏掉仍可手滚列表。
  - 验证信号：上翻离开底部 → 圆钮出现；点开拨动跳转到对应「你」消息并顶到屏幕顶部；旋转中到底不收起，松手 2.5s 后收起。

- **跳到底部按钮 + 自动跟随底部** `P1`
  最新消息不可见时悬浮「↓」按钮；默认跟随底部、用户上滑即暂停、滑回底部恢复（`canScrollBackward` 判定）。
  - 故障影响：坏掉 = 新消息不自动滚到底，用户错过实时回复（体验，可手动滚，P1）。
  - 验证信号：上滑浏览历史 → 按钮出现；点它回底部且恢复跟随；发消息后自动贴底。

- **思考流式行 + 思考卡** `P2`
  `think_delta` 实时一行刷新「思考中」；`think` 事件渲染「思考」浓缩行，长按复制全文。
  - 故障影响：纯展示增强，坏掉不影响遥控。
  - 验证信号：agent 思考时底部出现「💭 思考中」流式行，完成后转为「思考」卡。

- **长按复制** `P2`
  消息/思考/工具卡/结果卡/上下文行长按复制到剪贴板 + 触感反馈。
  - 故障影响：便捷功能，坏掉不影响核心。
  - 验证信号：长按任意消息 → 剪贴板含原文。

## 7. 子代理会话

- **子代理列表（状态/元信息/上限 10 滚动）** `P1`
  主会话顶栏「🤖N」下拉列出 `parentSessionId` 匹配的子代理，副标题含状态 + 最后消息时间/运行时长/token（`MetaFormat` 紧凑格式），上限 10 条内滚动。
  - 故障影响：看不到子代理 = 无法进入其会话（遥控子代理受阻）；注意 bug 案例：下拉内不能用 `LazyColumn`（intrinsic 崩溃）。
  - 验证信号：点「🤖N」→ 下拉列出子代理且不崩溃；副标题元信息来自服务端投影（`lastMessageAt/runDurationMs/totalTokens`）。

- **进入子代理会话 + 返回主会话** `P1`
  `openSubagent` 记录 `subagentReturnTo` 后 `openSession`；返回键/← 回主会话。
  - 故障影响：坏掉 = 子代理会话打不开或回不去主会话（导航类，P1）。
  - 验证信号：进子代理 → 顶栏显示「🤖 子会话」；按返回回到主会话而非退出。

## 8. 审批与提问（中断式强提醒）

- **审批半屏弹窗 + 裁决回传** `P0`
  `ApprovalSheet` 中断式半屏（禁止下滑/返回/点外部关闭），「允许一次/拒绝」；`approve` 按 bridge 持有走 `approve`、桌面端 mux 持有走 `answer_approval`（rpcId 判别）；到达时 `platformVibrateApproval` 双短振+长振。
  - 故障影响：审批收不到或裁决发不回 = 桌面 agent 卡在越权操作等待裁决，遥控人机协作咽喉堵死（P0）。
  - 验证信号：桌面端触发需审批工具 → 手机振动 + 半屏「等待审批」弹窗；点「允许一次」→ 弹窗关、桌面放行；`ConnLog` 见「收到审批 … 裁决审批」。

- **提问弹窗 + 回答回传** `P0`
  `QuestionSheet` 透传多问（单选/多选/自定义文本），全部作答后可提交 `answer_question`；到达时振动。
  - 故障影响：提问收不到或答不回 = agent 卡在 `ask_user_question` 等待输入（P0：与审批同级的协作咽喉）。
  - 验证信号：触发 `ask_user_question` → 手机「等待回答」弹窗列出问题与选项 → 提交后桌面收到回答。

- **重连/新连接补发 pending 审批与提问** `P0`
  `hello` 携带 `pendingApprovals`/`pendingRemoteApprovals`/`pendingQuestions`，重连后据此重建待裁决队列（唯一事实源）。
  - 故障影响：补发丢失 = 断线期间的审批/提问被吞，agent 永久挂起且用户无感知（P0：状态正确性 + 咽喉）。
  - 验证信号：断线前桌面有 pending 审批 → 重连后 hello 到达立即弹窗，无需重新触发；`ConnLog` 见「收到 hello … pendingApprovals=N」。

- **审批/提问振动强提醒** `P1`
  新审批/提问到达时振动（非重复项才振）。
  - 故障影响：无振动仍会弹窗，只是可能错过（强提醒的物理层，P1）。
  - 验证信号：息屏/后台收到审批 → 手机振动提醒。

## 9. 状态投影

- **hello 对账（快照唯一事实源）** `P0`
  `handle(Hello)` 用服务端快照 diff 会话列表（新增/更新/删除），校验 `selectedWorkspaceId`/`currentSessionId`/`subagentReturnTo` 有效性，清理幽灵会话，重订阅当前会话。
  - 故障影响：对账错乱 = 会话列表/当前会话与桌面端不一致，用户遥控错会话（P0：状态一致性的根）。
  - 验证信号：桌面端新建/关闭会话 → 手机列表实时增删；`ConnLog` 见「会话对账 新增=X 更新=Y 删除=Z」。

- **增量状态事件（agent_status / session_queue / session_upsert / session_title）** `P0`
  运行状态、队列、列表增量的实时广播，驱动会话列表状态点、排队面板、标题。
  - 故障影响：推不过来 = 状态点/队列/标题全部错乱（核心支柱②）。
  - 验证信号：会话运行中状态点变绿、运行结束变灰；队列变化即时反映。

- **Deep Diving 指示 + 服务端时钟** `P1`
  `turn_status` 开/关轮次标签；`deep_diving_tick` 每秒推服务端 elapsed 秒数（客户端不本地计时，铁律 6）；≥15s 才显示时钟；`model_waiting`/`model_waiting_done` 驱动等待指示。
  - 故障影响：坏掉 = 看不到「agent 正在干活」的指示与耗时（体验，P1；注意 bug 案例：轮次级时钟只能在 `turn_status(closed)` 清，否则闪烁）。
  - 验证信号：运行中显示「🤿 Deep Diving」，≥15s 出现「本轮 N 秒」且随服务端 tick 递增。

- **会话级状态隔离（切会话不串扰）** `P1`
  `modelWaitingSince/divingTurnStart/deepDivingElapsed/todos/goal/debug/diagnostics/liveThink/commands` 全部按 `sessionId` 过滤/重置，子代理切换同样隔离。
  - 故障影响：串扰 = 上个会话的指示条/诊断/目标漏到新会话（状态错乱，P1）。
  - 验证信号：A 会话运行中切到 B → B 无 Deep Diving/排队/诊断残留（bug 修复 `e96a075`）。

- **goal / todos 面板（可折叠）** `P2`
  Goal 面板展示 objective/阶段/轮次/阻塞原因；任务列表展示进度统计（已完成/进行中/待处理，对齐 `progressLabel`）。
  - 故障影响：状态展示增强，坏掉不影响遥控。
  - 验证信号：会话有 goal → 「🎯 Goal」面板按阶段着色；`todo_write` 后「📋 任务」面板计数对齐服务端。

- **LSP 诊断展示** `P2`
  `diagnostics` 事件 → 开发状态行徽标（错误/警告计数）+ 详情面板（文件:行:列 + 消息），cap 100 条，绝不自动弹面板。
  - 故障影响：开发辅助，坏掉不影响遥控。
  - 验证信号：agent 编辑代码后状态行出现「N 诊断（M 错误）」；点开见具体文件行。

## 12. 持久化与缓存

- **草稿磁盘缓存** `P1`
  输入框内容 600ms 防抖落盘（`DraftCache`，按「设备 + 会话」key）；断线/切会话/重启不丢打字。
  - 故障影响：坏掉 = 未发送长文本丢失（体验，P1）。
  - 验证信号：输入半句话杀 App 重启 → 进同会话草稿原样恢复。

- **会话列表缓存（秒开 + 增量对账）** `P1`
  `SessionCache` 按 serverId 存 `CachedSessionSnapshot`；连接时 `hydrateFromSessionCache` 先渲染，hello 到达后增量覆盖。
  - 故障影响：坏掉 = 冷启动列表空白需等 hello（秒开体验，P1）。
  - 验证信号：弱网/断线启动 → 列表先显示缓存、随后对齐服务端。

- **事件窗口缓存（断线可读/秒开）** `P1`
  `EventCache` 按「端点 + 会话」存最近 500 条事件，2s 节流落盘；断线/重连期间仍可读已加载内容。
  - 故障影响：坏掉 = 断线期间打开会话空白（可读性，P1）。
  - 验证信号：断线后进会话 → 显示缓存内容；重连后以服务端历史为准覆盖。

- **设备凭据存储（原子写）** `P0`（并入「连接与配对」章节第 3 条）
  `DeviceStore` 互斥串行 + 临时文件原子写，防并发丢写与半写损坏。
  - 故障影响：凭据损坏/丢失 = 无法自动重连、phoneId 丢失（P0：连接稳定性底座）。
  - 验证信号：反复切换设备/重连后设备文件完整可读，无半写 JSON。

## 13. P0 清单汇总表

| 类别 | 子功能 | 故障影响 | 验证信号 |
|---|---|---|---|
| 连接 | WebSocket 建连与鉴权握手 | 连不上 = 全功能归零 | ConnLog「握手成功」；进入会话列表 |
| 连接 | 扫码配对（多候选） | 首次建连入口失效 | 扫码后设备入列表且「在线」 |
| 连接 | 设备注册 + 长期凭据持久化 | 无 token 无法自动重连 | register_device 发送；token/serverId 落盘 |
| 连接 | 断线自动重连（多候选退避） | 断线无法恢复 = 遥控中断 | 拔插 USB 后横幅出现→消失、数据保留 |
| 会话 | 进入会话（订阅 + 历史返回） | 打不开会话读不到消息 | 点会话秒开缓存、服务端历史覆盖 |
| 会话 | 发送消息（乐观入队 + 失败回滚） | 消息发不出 = 遥控失效 | 发消息出「你」气泡；断线时报错且回滚 |
| 会话 | 服务端实时事件推送（增量） | 看不到 agent 实时输出 | agent 发消息 300ms 内手机出现 |
| 队列 | 排队消息投影 + 插队/删除 | 运行中消息不可见/不可管理 | 运行中连发 → 面板计数、可 steer/remove |
| 审批 | 审批接收 + 裁决回传 | agent 卡死等待裁决 | 振动 + 半屏弹窗；裁决后桌面放行 |
| 提问 | 提问接收 + 回答回传 | agent 卡死等待输入 | 「等待回答」弹窗作答 → 桌面收到 |
| 审批/提问 | 重连补发 pending | 断线期间审批被吞 | 重连后 hello 到达即弹 pending |
| 投影 | hello 对账（唯一事实源） | 会话列表/当前会话错乱 | 桌面增删会话 → 手机实时同步 |
| 投影 | 增量状态事件广播 | 状态点/队列/标题错乱 | 运行状态点、队列、标题即时变化 |
| 持久化 | 设备凭据存储（原子写） | 凭据损坏无法自动重连 | 反复切换重连后设备文件完整 |

> P0 共 **13 条**（合并「设备凭据存储」后），覆盖两大支柱与审批/提问咽喉，控制在 12~18 条目标内。

## 14. 其他核心价值挖掘

以下能力用户未明确点名为 P0/P1，但按代码事实与「远程遥控」场景推演，值得纳入核心清单：

1. **发送可靠性（不静默丢弃 + 错误上抛）——跨所有命令的 P0 隐式前提**
   每个 `connection.send(...)` 失败都返回 `false` 并走 `pushConnectionError`，发送失败即显式报错（「未发送/发送失败」），绝不静默。这是「消息准确性」支柱的隐性底座：若无此约定，断线时用户会以为消息已发出而实际丢失。建议在回归验收中把它列为独立检查项。

2. **单向数据流 / 服务端投影为唯一事实源（铁律 6）——P0 级架构不变量**
   Deep Diving 时长用 `deep_diving_tick` 服务端秒数、子代理元信息用 `lastMessageAt/runDurationMs/totalTokens` 投影、消息分类用 `source` 投影，客户端零本地推算。这是「状态投影一致性」的根；一旦某处违规引入本地推算（如本地计时），必然复现 `计时器闪烁` 类 bug。建议作为代码审查红线。

3. **会话级状态隔离（切会话/子代理不串扰）——P1，但属于「关键状态错乱」边界**
   `openSession` 清空全部会话级状态、事件按 `sessionId` 过滤、子代理切换记录返回目标。历史上多次在此踩坑（Deep Diving/LSP 诊断跨会话串扰）。它贴近 P0 边界：串扰会「遥控错会话」，建议按 P1 高频回归。

4. **乐观显示 + 服务端广播纠正——消息准确性的关键设计**
   排队消息用 `local-` 前缀乐观入队、`session_queue` 到达后替换；历史翻页按 `seq-type` 去重防丢行。这套「先显示、后纠正」机制是消息及时性（100~300ms）与准确性兼得的核心手段，值得在验收中重点观察「乐观项是否正确被服务端替换」。

5. **内存/持久化防护（防 OOM / 防无界增长）——P1 稳定性底座**
   `MAX_EVENTS=500`、`MAX_ERRORS=20`、`ConnLog=1500`、`DIAL_SEEK_MAX_PAGES=10`、2s 节流落盘、10 分钟节流 `lastSeenAt`。这些上限保证长会话/长连接不崩、不丢写，是「连接稳定性」的隐性前提，建议在回归中抽查边界。

6. **多候选端点回退（USB → LAN → Tailscale）——P0 的隐蔽实现细节**
   `mergeEndpoints` 把当前端点置顶去重、`connectFromQr`/`connectDevice`/`startReconnect` 均逐候选快试（4s connectTimeout）。它决定「换网络后能否自动恢复」，是自动重连真正可用的前提，建议纳入连接验收场景矩阵。
