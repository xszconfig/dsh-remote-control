## 一、需求背景

- **为什么做这件事**：本项目是「手机端 Remote Control App」，开发闭环高度依赖 AI Agent 反复执行「改代码 → 编译 → 装机 → 验收」。当前每次改动都要走完整 Gradle 构建（Kotlin 2.1.0 / Gradle 8.11.1 / AGP 8.7.3 / KMP + Compose Multiplatform / minSdk 26），冷热路径都要几十秒到数分钟，Agent 迭代被编译耗时卡死。
- **核心诉求**：**不常驻打开 IDE**，只要一个「秒级编译服务」——常驻后台的编译 daemon + CLI，Agent 改完代码调它，几秒内产出增量产物/部署到真机。
- **为什么做这次调研**：依据铁律 1「重大选型在请示前必须先完成充分对比论证」，在聚焦腾讯音乐 Jugg 之前，需全景盘点大厂/社区所有「秒级编译 / 增量编译 / 热重载」框架，核实 Jugg 是否最优、是否存在被忽略的更强候选。
- **边界**：只做只读调研（web 检索 + GitHub API 元数据核实），不克隆、不安装、不构建、不改代码；本文件只回答「选谁」，不展开「无头编译服务」的具体架构（后者归 `Jugg秒编服务方案设计.md`）。

## 二、核心需求点拆解

1. **无头可 CLI 驱动**：不依赖 GUI IDE 窗口即可触发编译/部署（核心诉求）。
2. **适配 AI Agent 自动调用**：有 CLI 退出码 / JSON 输出 / MCP 等机器可读接口，无 GUI 交互步骤。
3. **Kotlin + Android + KMP + Compose Multiplatform 支持**：覆盖本工程 Kotlin 2.1.0 / Compose Multiplatform。
4. **秒级增量编译**：改动生效 ≤ 数秒，而非分钟级全量构建。
5. **部署能力**：能产出增量 APK / 热重载 / 热修复，落到华为真机。
6. **低集成成本 + 活跃维护**：不重写构建脚本、不强制接 SDK、上游仍在发版。

## 三、核心指标拆解

| 指标 | 达标口径 | 测量方法 |
| --- | --- | --- |
| 增量编译耗时 | 少量改动 ≤ 3 秒可见效果（Jugg 口径）；本工程 UI 层改动从「改完」到「可部署产物」≤ 5 秒 | 计时对比 Jugg 增量 vs 原生 Gradle |
| 无头性 | 无 IDE 窗口可触发（或可被 MVP 封装为常驻服务） | 观察是否依赖 IntelliJ 平台插件运行时 |
| Agent 可调用性 | 提供 CLI exit code / `--console=json` / MCP JSON-RPC | 解析输出结构、退出码语义 |
| KMP/Compose 覆盖 | 明确支持 KMP + Compose Multiplatform，兼容 Kotlin 2.1.0 | 对照官方兼容矩阵 |
| 部署可达性 | 产出 APK 或热重载到真机（华为 EMUI/HarmonyOS Android） | 装机 + `startup-smoke-test` 冒烟 |
| 资源占用 | 常驻 daemon 在 16GB M2 Air 上可接受（不显著挤占 Gradle/Kotlin daemon） | 观测常驻内存 |

## 四、预期收益

- **Agent 迭代提速**：把「改代码 → 看到结果」从分钟级压到秒级，直接放大 AI coding 的反馈闭环速度。
- **不绑 IDE**：摆脱「必须开着 Android Studio」才能秒编的约束，编译能力下沉为后台服务，可被任意 Agent/脚本调用。
- **减少重复构建**：增量编译跳过无关 Gradle 工作，节省机器资源与等待时间（Jugg 官方口径：10+ 工程、80 万+ 次增量编译、3.6 万+ 小时等待节省）。

## 五、候选方案全景与机制原理

按「与 Gradle 的关系」分为四类：

### A 类 · 复用/旁路 Gradle 的增量编译 + 部署（最贴近「编译服务」）

- **Jugg（腾讯音乐，tencentmusic/jugg）**：Android Studio 插件 + CLI + MCP。**机制**：复用最近一次完整 Gradle 构建为基线 → 识别源码/资源/依赖/类关系变化与影响面 → 只编译必要内容（Java、Kotlin、D8、增量资源工具链）→ 部署（热重载/热修复/增量 APK/重装）；超出增量路径时回退 Gradle 重建基线。**关键**：官方列明支持 **KMP + Compose Multiplatform**，兼容 Kotlin 1.3–2.2 / AGP 3.4–9.1 / Gradle 5.4.1–9.2.1，**本工程（Kotlin 2.1.0 / AGP 8.7.3 / Gradle 8.11.1）完全落在支持范围内**。
- **Gradle 原生（基线对照）**：Gradle daemon 本身就是常驻编译进程，`./gradlew` 即 CLI；叠加 configuration cache + build cache + Kotlin 增量编译，增量路径可到秒级，但无毫秒热替换、冷路径仍全量。

### B 类 · 旁路 Gradle 的 daemon 构建系统（迁移成本高）

- **Bazel（Google）**：daemon + 动作图 + 精确增量 + 内容寻址缓存，CLI/JSON 头等公民；Kotlin 靠社区 `rules_kotlin`，**KMP 支持弱**（官方 Slack 自认不够好）。
- **Buck2（Meta）**：Rust 重写的 daemon 构建系统，prelude 自带 `kotlin_library`/`android_*` 规则；**KMP 无成熟规则集**。

### C 类 · Compose 秒级热重载（只换 UI 代码，不产完整 APK）

- **Compose Hot Reload（JetBrains 官方）**：Gradle 插件 + Kotlin 编译器插桩 + JetBrains Runtime HotSwap；CLI 可驱动（`./gradlew :app:hotRunJvm` / `:app:reload` / `--autoReload`），**原生带 MCP server**（`status/reload/take_screenshot/get_semantic_tree/click` 等，专为 AI Agent 设计）；但**仅 Desktop JVM target，不落 Android 真机**，且要求 Kotlin 2.1.20+。
- **Compose HotSwan（skydoves 社区）**：唯一能在 **Android 真机**做 Compose 秒级热重载的方案（增量编译改动类 → push 设备 → recompose，含状态保留）；但它是 **AS 插件（需开 IDE）+ 付费 + Kotlin 2.3.0+ + 设备 API 28+**。

### D 类 · headless 分析/构建协议 & 早期工具 & 已死项目

- **BSP / LSP（fwcd/kotlin-language-server、JetBrains kotlin-lsp）**：只能做 headless 诊断/分析，**不产出 APK**，不能当「编译服务」。
- **Amper / Kotlin Toolchain（JetBrains）**：Amper 已 archive（2026-05），并入 Kotlin Toolchain（0.11）；CLI 构建工具，Android 支持实验性，太早期。
- **Freeline（阿里）**：历史上正是「CLI + daemon 旁路 Gradle 秒级编译 + 热替换」，但最后 push 于 2020-05，AGP 2.x/3.x 时代，Kotlin 支持弱，与 AGP 8.7.3/Kotlin 2.1 完全不兼容。
- **Fleet backend（JetBrains）**：headless IDE 进程路线已断（2025-12-22 停止下载、官方 discontinue）。
- **JRebel for Android**：停更 + 收费。
- **ByteX（字节）**：字节码 transform 平台（AGP Transform + ASM），非编译提速 daemon，已 archive（2024-01）；字节的「秒级编译」是内部工程实践（Gradle 缓存 + 云端差分缓存），**无开源编译 daemon**。
- **bk-turbo（腾讯蓝鲸）**：分布式编译（distcc 类，面向 C/C++），GitHub 已 404（下线），不面向 Kotlin/Android。
- **快手 / 美团 / 小米**：经中英文检索，**无面向 Android/Kotlin 的开源秒级编译框架**；快手重 KMP 但未开源编译加速工具；美团开源的是 Picasso 跨平台动态化框架（非编译提速）。

## 七、最终选择与决策逻辑（为什么聚焦 Jugg）

**结论：聚焦腾讯音乐 Jugg，作为「秒级编译服务」的基座，由用户于 2026-09-05 九项决策中拍板「Jugg 无头编译服务 MVP（2-5 人日）」。**

对照第六节逐条论证：

1. **无头可行性**：表面看 Jugg 的 CLI/MCP 都经「打开的 AS 工程里的 Jugg 插件运行时」承载，**没有现成的独立 headless daemon**——这是唯一短板。但相比其它候选：Freeline 已死、HotSwan 同样要开 IDE 且付费、Compose Hot Reload 不落真机、Bazel/Buck2 KMP 落地贵。**Jugg 是唯一「KMP 支持完整 + 秒级增量 + CLI/MCP 已具备」的候选**，其「无头」缺口可被 MVP（把 Jugg 插件运行时封装为常驻后台编译服务）补上，而这正是 `Jugg秒编服务方案设计.md` 要解决的核心命题。
2. **增量编译机制**：Jugg 复用 Gradle 基线、只编译变化影响面，3 秒级生效，且带部署（热重载/热修复/增量 APK/重装）——比 Gradle 原生更快、比 Freeline 更兼容现代工具链。
3. **KMP 支持**：Jugg 官方列明支持 **KMP + Compose Multiplatform**，兼容矩阵覆盖本工程 Kotlin 2.1.0 / AGP 8.7.3 / Gradle 8.11.1 / minSdk 26；Compose Hot Reload 仅 Desktop JVM、Bazel/Buck2 KMP 不成熟，均不满足「本工程 KMP + 真机」双要求。
4. **集成成本**：Jugg 仅装插件、不改 Gradle 脚本、不接 SDK，与原生 App Run Configuration 并行、可随时回退；Bazel/Buck2 需重写构建、迁移成本人周级。
5. **维护状态**：Jugg 活跃（push 2026-09-05）、MIT 开源、规模验证充分（全民 K 歌/QQ 音乐/JOOX/WeSing/酷狗/QQ 浏览器/央视频等 10+ 工程、80 万+ 次增量编译）；Freeline/ByteX/Fleet/JRebel/bk-turbo 均已死或下线。
6. **AI Agent 适配**：Jugg 原生提供 `jugg` CLI（`--console=plain|json`、`--project-dir`、`--if-compiling`）、本地 MCP（JSON-RPC，端口 12320–12329，`status/compile/deploy/layout-dump/tap/wait-logs` 等）与 `jugg-android-dev-loop` Agent Skill（edit → compile → deploy → verify）——**三者齐备，正是「AI coding 秒级编译服务」最需要的形态**。

**为什么不选其它**（一句话）：Freeline 死（AGP 2.x/3.x）；Bazel/Buck2 KMP 弱 + 迁移贵；Compose Hot Reload 不落真机；HotSwan 开 IDE + 付费 + Kotlin 2.3.0；Amper/Kotlin Toolchain 太早期；BSP/LSP 不产 APK；字节/快手/美团/小米无开源秒编框架。

**与 `docs/decisions/Jugg秒编服务方案设计.md` 的关系**：本文件是「选型论证前置」，回答「为什么是 Jugg」；该方案设计文档承接落地，回答「如何把 Jugg 封装成不常开 IDE 的常驻编译服务 daemon」（含 CLI/MCP 协议、与 Gradle daemon/Kotlin daemon 的进程关系、华为真机部署链路、资源占用）。二者交叉引用：此处只给结论与依据，架构细节一律指到方案设计文档。

## 八、对现有架构的影响

- **改动面（当前阶段）**：本文件为调研论证，**无代码改动**；后续 MVP 属独立新组件（编译服务 daemon），不侵入现有 App / Bridge 主链路。
- **风险点**：① Jugg CLI/MCP 依赖 IntelliJ 平台插件运行时，「无头 daemon」需评估 headless 模式下插件能力是否完整（如 UI 依赖、文件监听、JBR 依赖）；② 兼容矩阵为「已验证范围」，本工程若后续升级 Kotlin >2.2 或 AGP >9.1 需复测边界；③ 华为真机（EMUI/HarmonyOS Android）部署需验证 Jugg 部署路径与现有 huawei-adb 系列流程的衔接。
- **兼容性/回滚**：Jugg 与原生 App Run Configuration 并行、完全独立，超出增量路径自动回退 Gradle；即便 MVP 失败，随时退回现有 `./gradlew` + huawei-adb 装机流程，无锁死风险。

## 九、后续迭代规划

- **近期**：MVP（2-5 人日）——封装 Jugg 为常驻后台编译服务，暴露 CLI/MCP 给 Agent；先验证「本工程 UI 层改动 → 秒级增量产物」核心链路。
- **验收**：增量编译 ≤ 5 秒 + 华为真机部署 + `startup-smoke-test` 冒烟通过，按铁律 8/11 走「编译 → 装机 → 自动验收」。
- **已知限制**：Jugg 无独立 headless daemon（需 MVP 补缺口）；CLI/MCP 需工程在 IDE 中初始化过基线。
- **触发再评估的条件**：Kotlin 升 2.3+、AGP 升 9.1+ 或迁移 Bazel/Buck2 被提上议程时，重跑本对比；若 JetBrains Compose Hot Reload 补齐 Android 真机 target、或 Kotlin Toolchain Android 支持成熟，一并纳入复评。
