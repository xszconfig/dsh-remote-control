# 子代理嵌套浏览对齐调研（DSH Web → 手机 App）

> 目的：手机 App 的子代理列表目前只显示**一级**（顶层会话下的直接子代理，二级起不显示）。本调研只读解剖 DSH Web 的子代理导航实现，提炼可直接复用到手机 App 的结论，供会话域代理（4517b8d7）实现「按 `parentSessionId` 树形展开、无限层级嵌套」时参照。**本文件不落地任何 App 代码。**

---

## 一、手机 App 现状（要改什么）

- 会话列表只展示顶层会话（`parentSessionId == null`），子代理会话挂在主会话里（`SessionList.kt` L49-51）。
- 子代理数 `subagentCount = state.sessions.count { it.parentSessionId == s.id }`（`SessionList.kt` L92-93）——**只统计直接子代理，一级**。
- 进入子代理用 `openSubagent(subagentId)` + `subagentReturnTo`（记录「返回主会话」目标，`BridgeClient.kt` L650-656），**当前只有一级返回**（`subagentReturnTo` 单值，非栈）。
- 目标：子代理会话自身也能展示其子代理（二级、三级…），树形展开，对齐 DSH Web 的浏览效果。

## 二、DSH Web 实现解剖（只读调研，代码在 DSH checkout `@deepseek-ai/` 下）

### 2.1 渲染入口：会话头面包屑 `SubagentHeaderLineage`

- 消费方 `dsh-client-ui-conversation/lib/client.js` L7338-7362：`ancestry.map(...)` 逐层渲染面包屑；对每层 `renderSlot("conversation.session.header.lineage", lineageOwner)`。
- `lineageOwner = { lineageSessionId, displayTitle, ...(last ? {} : { openTitle }) }`——**只有最后一项（当前会话）不传 `openTitle`**。
- 组件本体 `dsh-client-ui-subagent/lib/client.js` `SubagentHeaderLineage`（L673-703）：
  - 顶层会话（`parentId === void 0`）→ 只渲染「后代计数下拉」`CatalogDropdown variant="count"`（rooted=自身）。
  - **子代理会话**（`parentId !== void 0`）→ 渲染「同级切换器 `variant="switcher"`（rooted=父，current=自身）」+ **当 `openTitle === void 0`（即当前会话）时再渲染「自身后代计数下拉」`variant="count"`（rooted=自身）**。
  - **结论**：Web 对「当前子代理」确实会展示它自己的子代理列表（计数下拉）。

### 2.2 计数下拉 `CatalogDropdown`（L404-667）与懒加载树

- `descendants = indexSubagentDescendants(byId).get(rootSessionId)`（L425）。
- **可见性门（关键）** L562：
  `visible = presentedCatalog !== undefined && (variant === "switcher" || state === "error" || entries.length > 0 || descendantCount > 0)`。
  对 `variant="count"`：只有 `descendantCount > 0` 才显示下拉（`descendantCount = max(catalog 直接子项数, descendants.count)`）。
- **懒加载**：树节点带 `hasChildren` 披露箭头；`toggleBranch(childSessionId)`（L514-521）→ `observeCatalog(childSessionId, true)` → `setCatalogOpen(childSessionId, true)` → 运行时 `refreshSubagents(childSessionId)` 只拉**该父的直接子项**（不预拉整棵树）。展开一个分支先渲染 N 个禁用 loading 行，再逐条替换为该子目录的权威条目。
- **目录请求**：`refresh(parentSessionId)` 按父会话 id 拉「直接子代理列表」（`ctx.subagents.listChildren(parentSessionId)`），与 Web `session.list` 的 `parentSessionId` 投影同源。
- **注意**：`variant="count"` 变体**不**像 switcher 那样在挂载时自动 `refresh`（L435-444 的自动 refresh 仅对 `variant==="switcher"`）——count 变体依赖 `byId` 里已有孙代摘要来显示计数。这是 Web 端一个已知的时序脆弱点（孙代摘要未进 `byId` 时计数下拉会被隐藏）。

### 2.3 后代累加计数 `indexSubagentDescendants`（`dsh-client-runtime/lib/client.js` L10267-10288）

```js
function indexSubagentDescendants(summaries) {
  const indexed = new Map();
  for (const descendant of Object.values(summaries)) {
    if (descendant.origin !== "subagent") continue;
    const seen = new Set();                       // 防环
    let current = descendant;
    while (current?.origin === "subagent" && current.parentId !== void 0 && !seen.has(current.id)) {
      seen.add(current.id);
      const agg = indexed.get(current.parentId);
      agg ? (agg.count += 1, descendant.running && agg.runningCount++) 
          : indexed.set(current.parentId, { count: 1, runningCount: descendant.running ? 1 : 0 });
      current = summaries[current.parentId];      // 沿 parentId 链向上累加
    }
  }
  return indexed;
}
```

- **语义**：每个 `origin === "subagent"` 的会话，沿 `parentId` 链**向上给每个祖先的 `parentId` 累加 count**（用 seen 集合防环）。结果 `indexed.get(X)` = X 的全部后代数（含孙代、曾孙代），不是只直接子代。
- **含 runningCount**：`descendant.running` 为真时，沿链每个祖先的 runningCount 也 +1（用于「N 个子代理，正在运行」的活动态）。

### 2.4 宿主侧数据：嵌套子代理的 parentId 正确性

- `dsh-subagent/lib/index.js` L536-537：子代理 header `{ parentSession: parentHeader.id, origin: "subagent" }`。
- `dsh-subagent/lib/index.js` L1249：`parentSession: parent.id`。
- **结论**：嵌套子代理（子代理再 spawn 的子代理）的 `parentSession` = **直接父会话 id**（不是顶层 id），`origin = "subagent"`。所以 `parentId` 链是「直接父链」，树形展开的锚点正确。

### 2.5 客户端摘要字段

- `dsh-client-runtime/lib/types/client/sessions/service.d.ts` L43-45：客户端会话摘要用 **`parentId?: SessionId`** + **`origin?: 'subagent'`**（Web 客户端把 wire 的 `parentSessionId` 映射为内部 `parentId`）。

## 三、手机端可复用结论（映射到 App）

| Web 机制 | 手机 App 对应 |
|---|---|
| `parentId` 链（直接父）+ `origin` | App 已有 `SessionSummary.parentSessionId`（服务端投影，bridge `SessionSummary` 已带）。**铁律 6：客户端只按 `parentSessionId` 建树，不推算**。 |
| `indexSubagentDescendants` 沿链累加 count/runningCount | App 端写一个纯函数 `subagentDescendantsByParent(sessions: List<SessionSummary>): Map<parentId, {count, runningCount}>`——沿 `parentSessionId` 链向上累加，防环（可抽纯函数单测）。用于每层节点的「🤖N / 运行中」计数（现状 `SessionList.kt` L92-93 只 count 直接子代，需换成累加或递归子树计数）。 |
| `CatalogDropdown` 懒加载树（`hasChildren` 披露 + `refreshSubagents(parentId)` 拉直接子项） | App 两种策略：①（推荐，会话量小）**全量建树**——`state.sessions` 已含所有会话与 `parentSessionId`，直接按 parentId 分组递归建树，展开节点零请求；② 懒加载（对齐 Web）——展开时才请求 `listChildren(parentId)`。**建议先①**，成本低、与「服务端投影为准」一致（数据已在 `hello` 全量下发）。 |
| 计数下拉 `visible` 门（`descendantCount > 0`） | App 侧：某父节点若有后代（`parentSessionId == 该id` 的子代理数 > 0）才显示展开箭头/🤖N；无后代显示叶子（对齐 Web 的 `hasChildren` 提示，避免无箭头误导）。 |
| `openSubagent` 导航 + 面包屑返回 | App 现状 `subagentReturnTo` 是**单值**（只记一层返回）。支持多级嵌套需改成**返回链/栈**（如 `List<String>` 或复用 Web 的 ancestry 语义），返回键逐级回退到直接父，而非直接跳顶层。 |
| 子代理会话只在父级入口展示（侧边栏排除） | App 现状已如此（`SessionList.kt` L49 只列顶层）。多级时：子代理会话也应从顶层列表排除，只在父节点下展开出现（现状子代理已被排除，保持一致即可）。 |

### 关键取舍（建议写进实现）

1. **全量建树 vs 懒加载**：App 会话量小（几十个），`hello` 已全量下发 `parentSessionId`，**首选全量建树**（纯函数 `buildSubagentTree(sessions)` + 展开/折叠由 UI 本地状态控制），避免懒加载的时序脆弱点（Web 端 count 变体不自动 refresh 正是此坑）。
2. **返回链**：`subagentReturnTo: String?` → 需支持多级。若为手机端最小改动，可保留 `subagentReturnTo` 记录「直接父」，进入更深层时入栈；返回键逐级 pop。具体形态由会话域代理定（栈 vs 单值 + 父链从 `parentSessionId` 反查）。
3. **计数口径**：`🤖N` 用「直接子代 + 递归后代」还是「仅直接子代」要对齐 DSH Web（Web 是**后代总数**，含孙代）。建议 App 也统一为后代总数（沿链累加），与 Web 一致。

---

## 四、结论

DSH Web 的嵌套子代理浏览 = **「`parentId` 直接父链 + 每层懒加载直接子项 + 后代沿链累加计数 + 当前节点显示自身计数下拉」**。手机 App 已具备数据底座（`parentSessionId` 全量下发），缺的是：①按 parentId 递归建树的展示层；②后代累加计数（替代现状只 count 直接子代）；③多级返回链（替代单值 `subagentReturnTo`）。建议全量建树 + 纯函数可单测，不引入懒加载时序风险。
