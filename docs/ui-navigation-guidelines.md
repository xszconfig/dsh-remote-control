# 页面层级与返回键规范（Memory）

> 记录于 2026-08-29：用户反馈「会话详情 → 连接日志 → 按返回键直接退到桌面」。
> 这是通用交互原则，**每次新增页面/覆盖层都必须遵守**；改完自查一遍。

## 核心原则：页面栈（Page Stack）

1. **从页面 A 跳到页面 B，再跳到页面 C：按一次返回键回到 B，再按一次回到 A。**
2. **每一次按返回键都只回到上一级页面**，绝不跳级、绝不在非根页面直接退出应用。
3. 根页面（首页落地页/工作区抽屉）按返回键才是退出到桌面。
4. 每个全屏页面/覆盖层都要有返回处理，且**返回行为必须与其可视返回控件一致**
   （左上角「←」按钮和系统返回键做同一件事）。

## 本项目实现方式

- 覆盖层页面（日志页、设备页）用状态位（`showLogs`/`showDevices`）显示：
  关闭状态位即回到上一级——**底下的页面状态（currentSessionId、选中工作区等）原样保留**，
  天然满足「回到上一级」；
- 每个覆盖层/全屏页必须配 `PlatformBackHandler`（后注册者优先，覆盖层打开时独占返回键）；
- 主界面内的层级（会话详情 → 会话列表 → 工作区抽屉）分别由 `Conversation`、
  `MainScreen` 的 BackHandler 按 enabled 状态互斥处理（见 `feat(nav)` 提交）。

## 历史坑（根因记录）

1. **日志页没有返回处理**：从会话详情打开日志页后，底层 BackHandler 未挂载、
   日志页自身也没有拦截 → 系统默认行为直接 finish Activity 退桌面。
   修复：`showLogs` 分支补 `PlatformBackHandler { showLogs = false }`；
   顺带发现**扫码页**同样没有返回处理（返回 = 取消扫码），一并修复。

## 自查清单（新增/修改页面后）

- [ ] 这个页面能从哪里进入？每个入口对应一次「返回」能否回到进入前的那一页？
- [ ] 页面是否有可视返回控件（←/✕）？系统返回键是否与它行为一致？
- [ ] 全屏覆盖层/弹窗有没有 `PlatformBackHandler`？优先级是否正确（后注册者优先）？
- [ ] 根页面才允许「返回 = 退出」；其他页面一律返回上一级。
- [ ] 真机走一遍完整链路：A→B→C，连续按返回验证 C→B→A（不要只看一步）。
