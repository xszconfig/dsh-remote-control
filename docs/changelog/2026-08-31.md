## ✨ 斜杠命令移动端支持（/compact 等）
- **feat(bridge)**：`send_message` 斜杠命令路由——已注册命令（compact/plan/goal/feedback/export…）走 DSH `commands.execute`（与 Web composer 同一条执行链）；未注册命令回报会话内错误行、不发模型；非斜杠文本原样发模型（决策经用户确认：路由范围=所有已注册命令，未知命令=报错）

- **feat(app)**：输入 "/" 弹命令候选弹窗（名称 + 一句话说明、前缀过滤、聚焦才弹、点击填入 "/命令名 "）；命令结果行渲染（⏳ 执行中 / ✅ 成功 / ⚠️ 失败），running 与 done 按 commandId 合并单行

## ✨ 新功能 / 修复
- **feat(bridge)**：客户端主动打开服务端休眠会话并直接发消息——`send_message` 对无 live agent 的会话按 DSH Web 同款机制自动打开：顶层会话走 `ctx.agents.resume`（setup 里挂 agentPresets preset + 装模型选择，消息 await 就绪后 `followup` 投递，保证不丢）；子代理会话先 resume 父会话，再走官方 `ctx.subagents.followup` 冷恢复投递（子代理由 subagent 路由拥有，不能用通用 `agents.resume` 直接拉起，否则丢失 persona/toolFilter/父子归属）；打开失败仍回 `not_running` 并附原因。协议未变，客户端无需改动
- **feat(bridge)**：子代理会话列表标题凝练——标题不再用首个长 Prompt，改为创建工具调用里的 `description`（5~10 字凝练描述，经子会话自身 `subagent` 投影读取，零额外日志读取）；活会话 `displayTitleOf`/冷会话 `coldRowFromCache`/`session_title` 推送三处统一覆盖，无 description 回退原标题，普通会话标题不受影响
- **fix(bridge)**：自动续跑两个根因修复——①挂载等待久：boot 只有 20s 定时器（agent 早于 bridge 挂载时事件错过）+ 只监听 `agent/status running` 漏掉 idle 挂载；改为 boot 立即尝试一次 + 新增 `agent/created` 即时触发，20s 定时器降级纯兜底。②阻塞解除后连发 2~3 条续跑指令：cordis emit 同步派发 + `followup` 唤醒 idle agent 同步重入 `agent/status` 处理器，而指纹在 followup 之后才写盘 → 重入窗口重复注入；加进程内重入锁（`resumeInjecting`/`restoringSessions`），跨 tick 仍由磁盘指纹兜底
- **fix(bridge)**：Kotlin LSP 诊断失效修复——真实根因是 kotlin-lsp 自带 JBR-25（Java 25）与 Gradle 8.11.1 不兼容（`Unsupported class file major version 69`），叠加 `kotlinProjectRoot` 误把 composeApp 模块目录当项目根（读不到 wrapper → 选不到兼容 JDK → 导入失败 → 无 content root → 0 诊断）；改为根定位优先最上层 settings 目录 + spawn 环境注入兼容 JAVA_HOME（openjdk@21）/GRADLE_USER_HOME/剥离代理。实测导入成功且 `val x: Int = "..."` 返回真实 Kotlin 类型错误
- **feat(bridge)**：LSP 被动诊断反馈 Agent 自动闭环——Agent 编辑文件后诊断到达，severity=1 错误自动以 `agent.inject`（运行中 next-step 注入、不打断；空闲 `followup` 唤醒，plugin source）喂给 Agent；修复→复查→直到错误清零（~1s 防抖、指纹去重、每轮上限 3 次、进展语义、清零静默）；核心场景「改动遗漏引用处」跨文件覆盖：TS 通道复用 tsserver 受影响文件推送 + Kotlin 通道 pull 全部已打开文档 + 手机端不再丢弃 sessionId 为空的诊断；`DSH_REMOTE_LSP_FEEDBACK=0` 逃生门
- **test(app)**：修复预置坏掉的单元测试源码集编译（BridgeClient 构造参数对齐、ApprovalSettledLegacy 断言），`testDebugUnitTest` 跑通
- **feat(ui)**：任务列表条状态统计对齐服务端——总个数右侧按 DSH Web `progressLabel` 同款展示「X 已完成 · Y 进行中 · Z 待处理」（顺序固定已完成→进行中→待处理，零计数段省略，"·" 连接）
- **fix(ui)**：运行中「终止」与「发送」并存——之前"运行中发送按钮变终止按钮"导致客户端无法追加消息；改为运行中显示红色终止 + 发送双按钮，发送照常入队（与 DSH Web 一致）
- **fix(app)**：Deep Diving 计时器闪烁——`model_waiting_done` 误把轮次级时钟 `deepDivingElapsed` 一并清空（一轮中有多次模型调用，每次结束都广播一次 `model_waiting_done`，时钟被清掉、下个 tick ≤1s 才恢复）；改为只清 `modelWaitingSince`，轮次级时钟只在 `turn_status(closed)` 时清除（对齐 DSH Web：时钟锚定 OPEN 轮次起点，跨 first-token/tool/streaming 阶段保留）
