## 背景

- 装机是「编译 → 装机 → 自动验收」自迭代循环的根基（P0）。正常路径：USB 连接，`huawei-adb-fast-install` 固定坐标点掉华为安装器确认弹窗，全程 ~20s。
- 2026-09-04 USB 未插，唯一通道 = Tailscale adb（RTT ~375ms）；APK 12.6MB。

## 现象（当日失败时间线）

1. 240s 超时被杀（传输+确认流程超时）；
2. 「User rejected permissions」×2（确认弹窗点按落空——手机息屏 / 用户在使用微信）；
3. 手动重试多次被 `Error: tool call aborted` 打断；
4. 直跑 `adb install -r` 无任何输出、300s 超时（弹窗无人点，安装器挂起）；
5. **全程无进度显示**：包大小、传输进度、安装器是否调起、错误信息都没有暴露，开发者盲等。

## 排查过程

- 逐次检查：`adb devices`（USB 离线/Tailscale 在线/offline 抖动）、`dumpsys window mCurrentFocus`（息屏 → focus null；微信前台）、`lastUpdateTime`（确认安装未完成）、`/remote/logs` + 手机 ConnLog（发现两条 interrupt 命令与装机被杀时间吻合）。
- 根因证据链：桥日志 `items=3 → type=interrupt → items=0`；会话日志 splice 事件 `removedCount=3, outcome='canceled'`；inserted 事件还原出三条被清消息的全文。

## 根因分析（深层）

**表面原因**：Tailscale 高 RTT + 12.6MB 传输慢；华为安装器是交互式的、依赖屏幕状态；会话行「中断」按钮误触。

**深层根因（三条，均可推广）**：

1. **远程操作缺「可观测性」**：本地装机有屏幕可看，远程装机没有任何状态通道——传输进度、安装器调起、错误信息全部黑盒。开发者只能盲等+超时，失败后无现场可复盘。教训：**任何超过数秒的远程自动化，必须先设计"状态可见"**（进度、阶段、错误上抛到对话流），否则超时与失败无法区分。
2. **交互式安装器与"无人值守"假设冲突**：华为安装器的确认弹窗是安全机制，但自动化流程假设"屏幕亮着、无人在用"——两个假设都脆弱（息屏、用户在用微信/刷消息）。教训：**依赖第三方交互 UI 的自动化，必须检测屏幕状态并在失败时显式请求人工介入，而不是盲点固定坐标**。
3. **「终止」语义与用户心智模型错位**：会话行的「中断」按钮嵌在主点击区内（整行 Card 可点开会话，按钮在行内右下角），无确认。用户本意"停掉卡住的工具调用"，实际效果是"终止 agent loop + 清空排队消息"——**排队中的消息是用户的明确指令，被隐式清空 = 未经明确撤销就撤销了指令**（当日真实丢失 3 条用户指令，靠会话日志 splice 事件才捞回）。教训：**破坏性/不可逆操作（清队列、撤销指令）必须有等价的显式确认，且不能嵌套在更大的点击热区内**。

## 解法

- 已做：装机前唤醒屏幕 + `svc power stayon`；后台安装不受超时限制；手动配合点弹窗。
- 进行中：装机进度监控（包大小/传输进度/安装器调起状态/错误上抛到对话流）——用户明确要求，落地到装机流程。
- 待拍板（用户将讨论）：「终止」前若有排队消息 → 弹确认「终止并清空排队消息？」；无排队消息则直接终止；或让排队消息跨 agent loop 存活。
