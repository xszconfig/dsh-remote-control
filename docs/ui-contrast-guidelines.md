# UI 对比度规范（Memory）

> 记录于 2026-08-29：用户反馈日志页/会话列表「深色背景上黑色文字看不清」。
> 这是 UI 设计常识级原则，**每次新增/修改 UI 都必须遵守**；改完自查一遍。

## 核心原则

1. **内容颜色永远不能与背景同色或接近色**——要有足够对比度，人眼才能看到。
2. **深色背景 → 浅色（通常白色）文字；浅色背景 → 深色（通常黑色）文字。**
3. 小号文字（labelSmall/bodySmall/等宽日志行）需要比大标题更高的对比度。
4. 图标与背景同理（纸飞机图标「看不清」也是对比度问题）。

## 本项目的历史坑（根因记录）

1. **Material3 的 `MaterialTheme` 不提供 `LocalContentColor`**，其全局默认是**纯黑**。
   所有「没显式写颜色、且不在 Surface/Card/Button 内部」的 Text 都会渲染成黑字。
   深色主题下就是「深底黑字」。
   **修复**：`DshTheme` 里先 `CompositionLocalProvider(LocalContentColor provides onBackground)`
   再包 `MaterialTheme`——全局兜底默认内容色为浅色。新增主题或重构主题时不可去掉这一层。
2. **48dp 圆钮 + 默认 24dp 水平内边距 = 内容区 0 宽**：图标/文字被裁得一点不剩，
   只剩纯色圆（小飞机「没画出来」的真相）。小尺寸按钮必须 `contentPadding = PaddingValues(0.dp)`
   或很小的值。
3. **深底上的小号强调文字不要用 primary**：primary 为了按钮对比度调深后（#3057D5），
   它作为深底上的文字对比不足（~3:1）。统一用 `AccentBlue`（#9DB8FF，浅蓝，~8:1）。
4. 状态色如果「既是状态点颜色又是文字颜色」（如 `StatusGray`），取值要按**文字可读性**
   下限来定，不能太暗。

## 修改 UI 后的自查清单

- [ ] 每个 `Text` 确认前景/背景对比：黑底配白字、白底配黑字；
- [ ] 小按钮（<64dp）检查 contentPadding 是否把内容挤没；
- [ ] 新增颜色先算对比度（正文 ≥4.5:1，大标题/图形 ≥3:1）；
- [ ] 真机截图 + 像素采样验证（PIL 采样文字包围盒内的像素色，别只信代码）；
- [ ] 深色主题改完，把深/浅两态都过一眼。
